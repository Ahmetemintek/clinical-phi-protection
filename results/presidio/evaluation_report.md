# Presidio evaluation on ASQ-PHI (Stage 2D)

Baseline evaluation of saved Presidio predictions (default recognizers, no score threshold) against ASQ-PHI gold annotations. Generated by `benchmarking/evaluate_presidio.py`.

## Methodology

- **Matching:** strict one-to-one exact match on (start, end, standardized_label)
- **Offsets:** start inclusive, end exclusive, Python string (code point) indices
- **Duplicates:** a gold entity can be matched once; further predictions with the same key are FPs
- **Unmapped predictions:** excluded from all category metrics (not counted as FP); reported separately
- **Hard negatives:** mapped predictions on hard-negative records are FPs
- **Unresolved gold:** records containing an ambiguous/missing gold annotation are excluded entirely
- **Thresholds:** none; every saved prediction is used regardless of score
- **Zero denominators:** a metric is null when its denominator is 0; F1 = 2TP / (2TP + FP + FN)

## Key findings

- Overall: precision 0.425, recall 0.491, F1 0.456 over 2957 eligible gold annotations.
- Gold categories with no true positives: ACCOUNT_NUMBER, CERTIFICATE_LICENSE_NUMBER, FAX_NUMBER, HEALTH_PLAN_BENEFICIARY_NUMBER, MEDICAL_RECORD_NUMBER, UNIQUE_IDENTIFIER.
- Largest FP sources by Presidio label: DATE_TIME (1546), LOCATION (184), PERSON (169).
- 199 of 219 hard-negative records have predictions; 333 mapped predictions on them count as FPs.
- 510 unmapped predictions are excluded from the metrics; 197 of them have exactly the span of a gold entity.

## Limitations

- Exact matching counts a span that differs from gold by even one character as both an FP and an FN.
- Unmapped predictions are not penalised, so precision covers only the 7 mapped Presidio labels; Presidio has no mapped label for several ASQ-PHI categories.
- Gold labels follow ASQ-PHI annotation conventions, which may differ from Presidio's notion of each entity.
- Records with unresolved gold annotations are excluded, so a few real entities are not evaluated.
- Default Presidio configuration and a single run; results are a baseline, not a tuned system.
- The `fp_by_gold_relation` / `fn_by_prediction_relation` groups describe span overlap only; they are not semantic error types.
